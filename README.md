# Homological Observability

Homological Observability is a Python toolkit for studying which accumulated
cycle histories can be recovered from discrete observations of a known Markov
jump network. Use it to compare network structures, additional integer
readouts, and asymptotic sampling requirements, or to construct the critical
limit experiment for a model with known transition rates.

## Why homological observability?

Imagine a particle moving among three wells arranged around a ring, described
by a three-state Markov jump model. A detector records only the occupied well
every $\delta$ units of time. A pair of snapshots showing A and then B is
compatible with a direct jump A → B or two jumps A → C → B. The two histories
differ by one winding around the ring, but the snapshots are identical.

![Two paths on a three-state ring give the same snapshots: a direct A-to-B jump and the alternative A-to-C-to-B route differ by one cycle.](docs/snapshot_ambiguity.svg)

Knowing the transition rates gives probabilities to these alternatives; it
does not reveal which history occurred. Even at equilibrium, with equal
forward and reverse rates and zero mean cycle current, this ambiguity remains.
The quantity to recover is the accumulated integer cycle displacement of an
actual run, relative to a fixed endpoint reference.

Longer observation produces more snapshots **and a longer history to recover**.
For the triangle, a two-jump alternative has probability of order $\delta^2$
per window. Across about $T/\delta$ windows, its cumulative scale is $T\delta$.
On general networks, different cycle directions enter at different orders,
giving the scales $T\delta^{m-1}$. Times here are measured in a fixed reference
rate's inverse units. The software computes the integer structure that tells
these layers apart and identifies what additional readouts can distinguish.

## What you can learn with it

| Research question | Analysis | What the result lets you compare |
| --- | --- | --- |
| Which cycle histories can my snapshots leave ambiguous? | Supply a finite graph to `analyze` | Exposure layers and hidden cycle directions, including integer information that ordinary rank misses |
| What does an extra counter buy me? | Analyze the same graph with different integer readouts | Which hidden directions are removed and how the remaining layers change asymptotic sampling requirements |
| How do transition rates affect the ambiguity at a threshold? | Supply known exact rates to `critical` | Competing path probabilities and the marked-Poisson limit, including its visible-count and readout conditions |

These tasks accept your own supported networks. They automate exact lattice
and path calculations that would otherwise have to be repeated for each model.
Sampling exponents provide asymptotic comparisons; a finite-data error
probability requires further analysis of the corresponding observation model.

## What the software computes

The input is a finite connected simple graph $G$, zero or more integer edge
cochains defining a readout $\pi$, and optional resource and sampling
parameters. The package computes the following objects:

| Stage | Exact object | Scientific role |
| --- | --- | --- |
| Network topology | $\Lambda=H_1(G;\mathbb Z)$ | Independent integer cycle coordinates for accumulated history |
| Exposure | $L_m\subseteq\Lambda$ | History differences generated by competing paths of exposure order at most $m$; equivalently, by simple cycles of length at most $2m$ |
| Visible image | $\pi(L_m)$ | Exposed information retained by the side readout |
| Hidden lattice | $K_m=L_m\cap\ker\pi$ | Exposed ambiguity invisible to the readout |
| Graded structure | Successive quotients of $L_m$, $\pi(L_m)$, and $K_m$ | New free directions and finite-index effects at each layer |
| Information phase | Critical and snapshot-budget exponents | Theorem-derived asymptotic interpretation |

Integer arithmetic matters to the observation problem. A counter may reveal
the parity of a cycle count without determining the count itself. Such finite
information survives in integer quotients even when real ranks do not change;
the wedge example below makes this distinction explicit.

The package analyzes a supplied network and optional rates. The inputs are a
model and an observation specification, rather than a measured trajectory to
be fitted. See the [model guide](docs/MODEL_GUIDE.md) for the input contract.

## Install from a source checkout

Clone this repository and enter its root directory:

```bash
git clone https://github.com/yeruciwenrou-dotcom/homological-observability.git
cd homological-observability
```

Alternatively, download and extract the repository ZIP, then open a terminal
in the directory containing `quickstart.py`. Python 3.11–3.13 is supported.
To run the tests and reproduce the paper evidence, go directly to
[the verification quickstart](#verify-the-software-and-paper-evidence), which
handles installation for you. To install the package for analysis on macOS or
Linux, create and activate a virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
```

On Windows PowerShell, create the environment with `py -m venv .venv` and
activate it with `.venv\Scripts\Activate.ps1`. The CI configuration covers
Ubuntu and Windows.

## Two ways to start

### Explore the software

After completing the source installation above, run the built-in wedge example:

```bash
homological-observability example wedge-c3-c5
```

This is the fastest way to see a nontrivial exact analysis result.

To inspect the path ambiguity itself, the source checkout also provides a
finite-ring bridge calculation:

```bash
python explore_cycles.py --cycle 4 --residue 2 --delta 0.1
```

This prints winding probabilities given two opposite-vertex snapshots on a
symmetric four-state ring. The two shortest routes have equal weight. The
table reports the mass covered by its displayed winding range; it is a
single-window calculation for this model.

### Verify the software and paper evidence

From the repository root, run:

```bash
python quickstart.py
```

This path only requires Python 3.11–3.13 to be installed. The script creates
and manages its own `.venv`, installs the pinned dependencies, runs the
reader-side test suite, and reproduces the frozen paper evidence. It is the
verification entry point. On macOS or Linux, use `python3 quickstart.py` if
`python` is not available.

A successful run reports that the generated tables agree with the committed
reference results. Open `generated_results/REPORT.md` for the scientific

The quickstart installs the command-line tool into its own `.venv`. Before
using the commands below, activate that environment on macOS or Linux:

On Windows PowerShell, use `.venv\Scripts\Activate.ps1`. You can also run a

## Guided example: a wedge of C3 and C5

Two loops share a state. Suppose an extra counter measures $2n_3+n_5$, where
$n_3$ and $n_5$ are the triangle and five-cycle history coordinates. It reveals
the parity of $n_5$, yet cannot distinguish a change of $-1$ in $n_3$ together
with $+2$ in $n_5$. The analysis identifies when that hidden combination first
enters the exposure filtration.

Run the built-in example:

```bash
homological-observability example wedge-c3-c5
homological-observability example wedge-c3-c5 --format json
```

The network has two independent cycle directions. The triangle is exposed at
layer $m=2$; the five-cycle first appears at $m=3$. The chosen readout gives

$$
\pi(L_2)=2\mathbb Z,
\qquad
\pi(L_3)=\mathbb Z,
$$

so the new visible information at layer three contains the finite quotient

$$
\pi(L_3)/\pi(L_2)\cong\mathbb Z/2\mathbb Z.
$$

A hidden free direction appears at the same layer. The
[end-to-end guide](docs/END_TO_END_EXAMPLE.md) explains why this example
separates integer-lattice information from ordinary rank and how the hidden
direction enters the phase interpretation. Its frozen
[JSON](examples/wedge_c3_c5_result.json) and
[Markdown](examples/wedge_c3_c5_result.md) reports are generated from the
same public API.

## Analyze your own network

The smallest model contains a schema version, name, vertices, and undirected
edges:

```json
{
  "schema_version": 1,
  "name": "triangle",
  "vertices": ["a", "b", "c"],
  "edges": [["a", "b"], ["b", "c"], ["a", "c"]]
}
```

Save the document and run:

```bash
homological-observability analyze triangle.json
homological-observability analyze triangle.json --format json
```

Readouts are integer 1-cochains on oriented edges. Optional analysis settings
control `max_layer`, the `max_cycles` resource budget, and either the
asymptotic exponent `alpha` or the finite-scale pair `observation_time` and
`sampling_interval`. See the [model guide](docs/MODEL_GUIDE.md) for the full
input contract.

If `max_layer` stops before the exposure lattice reaches all of
$H_1(G;\mathbb Z)$, the result reports `PARTIAL_HORIZON`. Its requested layers
are exact, but it does not claim that higher layers contain no additional
directions.

Under the paper's Markov-process interpretation, every undirected edge
represents positive transition-rate support in both directions. Rate
magnitudes are unnecessary for this exact filtration. A process with a zero
rate in one direction requires a dynamics-aware filtration outside this
contract.

## Construct a rate-dependent critical experiment

When every positive directed edge rate is known, the independent `critical`
task constructs the exact path catalogue at layer $m$, stationary law, graded
marks, and theorem-derived marked-Poisson experiment:

```bash
homological-observability critical examples/biased_c4_critical.json
homological-observability critical examples/biased_c4_critical.json --format json
```

The [biased C4 guide](docs/CRITICAL_EXPERIMENT.md) follows a nonreversible
four-cycle whose two antipodal path marks have exact conditional probabilities
$4/5$ and $1/5$ before applying the extra readout. It also compares retaining
and removing that counter, separating path uncertainty from the ambiguity
left after all available observations. Its complete generated
[JSON result](examples/biased_c4_critical_result.json) is checked against the
same public API used by the command.

This task specifies the paper's critical limit
$T\delta^{m-1}\to\theta$. It does not infer rates, simulate trajectories, or
produce an exact posterior at finite $(T,\delta)$.

## Python API

The CLI and API serialize the same immutable result object:

```python
import homological_observability as ho

model = ho.load_model("examples/wedge_c3_c5.json")
result = ho.analyze_model(model)
document = ho.analysis_to_dict(result)

assert result.status is ho.AnalysisStatus.COMPLETE
assert document["filtration"]["layers"][3]["visible"]["graded_quotient"][
    "torsion_factors"
] == [2]
```

The stable top-level API includes topology and critical model loading, exact
analysis, schema access, the example registry, and deterministic JSON and text
renderers. The topology result additionally has a Markdown renderer.
Lower-level homology and lattice coordinates remain auditable, but their
individual matrix entries are not basis-independent scientific invariants.

## Evidence and interpretation boundaries

| Evidence category | What it supports |
| --- | --- |
| `EXACT_INTEGER` | Homology coordinates, lattice images and kernels, and Smith/Hermite invariants |
| `EXACT_COMBINATORIAL` | Complete finite cycle or directed-path enumeration within the declared resource budget |
| `EXACT_RATIONAL` | Directed-rate products, stationary probabilities, and critical intensities represented exactly |
| `ASYMPTOTIC_THEOREM` | Phase quantities obtained by applying the paper's asymptotic theorem |

Lattice and quotient calculations are exact over the integers. Cycle
enumeration is exact when the requested catalogue completes. A restricted but
completed horizon returns `PARTIAL_HORIZON`; an exhausted resource budget
returns `LIMIT_REACHED` without presenting a truncated filtration.

Phase labels and entropy coefficients are theorem-derived asymptotic
predictions. They are not simulations, finite-sample error bars, confidence
intervals, or empirical guarantees. The manuscript remains authoritative for
the general theorems, hypotheses, and proofs.

## Reproduce the paper evidence

Run the packaged reproduction task and compare generated tables with the
frozen references:

```bash
homological-observability reproduce --check --output-dir generated_results
```

The source-checkout shortcut `python quickstart.py` additionally runs the
independent tests. Generated output is kept separate from `results/`; neither
entry point overwrites the committed reference evidence.

Reference acceptance uses numerical comparison at the documented tolerances.
The SHA-256 values in machine-readable reproduction output identify the exact
files produced by that run; they are not cross-platform pass criteria. See the
[output contract](docs/OUTPUT_CONTRACT.md#artifact-roles) for details.

The frozen companion covers symmetric C3–C6 bridge posteriors, the C3/C4
critical kernels, the Poisson-averaged binomial MAP identity, and the
reciprocal-lattice peak mechanism.

The [report](results/REPORT.md) explains the physical distinction between an
unseen winding and a visible opportunity with an unknown route. The figure
below checks the accuracy of their limiting descriptions: its vertical axes
show approximation errors, rather than history-recovery probabilities.
